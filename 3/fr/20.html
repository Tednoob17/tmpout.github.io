Cet article court est une introduction à un script de commodité pour quiconque veut 
construire des noyaux Linux arbitraires et des images Debian bootables pour tester, déboguer,
ou quoi que ce soit. Il s'appelle easylkb et nous le maintiendrons ici :

https://github.com/deepseagirl/easylkb

///: Qu'est-ce que nous essayons de faire ?

Écrire un script simple pour faciliter et rendre plus accessible le débogage du noyau Linux.

Lorsque vous construisez le noyau, il n'y a que quelques étapes à effectuer :

- Télécharger le code source du noyau
- Configurer le code source du noyau avec les options souhaitées
- Compiler le noyau

Pour exécuter ce noyau, vous pouvez le construire dans une image Debian qui peut être démarrée
avec qemu. Nous adaptons create-image.sh de syzkaller pour cela.

Une fois que vous exécutez le noyau, vous pouvez le déboguer avec gdb !

///: Comment installer easylkb ?

Installer les prérequis :

  sudo apt install make gcc flex bison libncurses-dev libelf-dev libssl-dev
  sudo apt install debootstrap

Ensuite, clonez le dépôt et exécutez easylkb.py avec Python

///: Comment utiliser easylkb ?

Construire une version spécifique du noyau principal, utilisez l'option -k :

  $ easylkb -k 6.2

Construire un autre noyau dans un répertoire, utilisez l'option -p :

  $ easylkb -p path/to/linux/

Les options de ligne de commande sont liées à des parties spécifiques du processus de construction.

Pour (t)élécharger, (c)onfigurer et co(m)piler un noyau

  $ easylkb -k 6.2 -dcm

Pour construire une image (D)ebian à partir de ce noyau

  $ easylkb -k 6.2 -i

Pour (e)xécuter l'image générée :

  $ easylkb -k 6.2 -r

Combinez toutes ces étapes en une :

  $ easylkb -k 6.2 -a

Une fois terminé, il exécutera l'image construite avec qemu, and expose ssh and 
GDB debugging features accessible via localhost.

///: Comment ça marche ?

Voilà comment le script fonctionne sous le capot :

- Télécharger le tarball du noyau Linux depuis le référentiel du code source du noyau sur kernel.org
- Appliquer les options KConfig qui le rendent bootable avec QEMU et débogable avec GDB
- Compiler le noyau using make
- Créer une image Debian bootable avec create-image.sh

Avec l'option -r, le script exécute l'image bootable avec QEMU, avec SSH et
débogage à distance avec gdb activé.

///: Comment interagir avec l'image ?

L'image, les clés et le script d'exécution sont stockés dans le répertoire img/ du 
code source du noyau.

Vous pouvez vous connecter en SSH à votre image comme suit :

  $ ssh root@localhost -p 10021 -i ~/kernel/linux-6.2/img/bullseye.id_rsa

La connexion par défaut pour l'image résultante est l'utilisateur "root" sans mot de passe.

Voici un exemple d'entrée de configuration SSH pour l'image résultante, que vous pouvez 
ajouter à votre fichier ~/.ssh/config.

Host linux62
  HostName localhost
  User root
  Port 10021
  IdentityFile ~/kernel/linux-6.2/img/bullseye.id_rsa
  StrictHostKeyChecking no

Maintenant vous pouvez vous connecter en SSH à votre noyau en faisant :

  $ ssh linux62

Vous pouvez copier des fichiers avec scp en faisant

  $ scp myfile.bin linux62:

Vous pouvez utiliser gdb pour déboguer comme suit :

  $ gdb ./vmlinux some other args

///: Débogage du noyau

/!\ NOTE : Si vous utilisez le noyau 5.18 ou supérieur, you may need to add 
          `CONFIG_DEBUG_INFO_DWARF4=y` to the end of your kconfig! A 
          recent change affects what options enable kernel debugging.

Pour déboguer le noyau, vous avez besoin $KERNEL_DIR/scripts/gdb/vmlinux-gdb.py

Ajoutez ceci à votre fichier ~/.gdbinit si vous voulez déboguer ce noyau, changing
the path to the kernel source you're working with.

add-auto-load-safe-path /home/user/kernel/linux-6.2/scripts/gdb/vmlinux-gdb.py

Maintenant, pour déboguer, faites simplement :

  $ cd /path/to/your/kernel/
  $ gdb ./vmlinux

Once you're in gdb just do this:

  (gdb) lx-symbols
  (gdb) target remote :1234

Wow ! Vous déboguez le noyau que vous venez de construire, assez sympa.

Essayez de mettre un point d'arrêt sur load_elf_binary et d'exécuter "whoami" dans
l'image Linux en cours d'exécution.

  (gdb) break load_elf_binary
  (gdb) continue

Lorsque le point d'arrêt est atteint, inspectez la structure bprm qui représente le
programme binaire.

  (gdb) p *bprm

Ensuite, vous pouvez utiliser la commande "step" pour avancer pas à pas dans le chargeur ELF du noyau !

Pour plus d'informations sur le débogage du noyau avec gdb :
- https://docs.kernel.org/dev-tools/gdb-kernel-debugging.html
- https://github.com/torvalds/linux
