Linux.Linkin.pl: Another Perl x64 ELF virus            │                   █   │

Encore un autre virus ELF x64 proof-of-concept écrit en Perl :

 * Il fonctionne en modifiant le dernier octet (instruction de retour) de la section .fini
   puis en injectant un payload dans l'espace libre (octets nuls) entre les
   sections .fini et .rodata. L'infection n'a lieu que si l'espace libre est
   supérieur à la taille du payload + taille du virus.

 * Le payload et la réplication sont exécutés après que le programme principal a été exécuté 
   (à la terminaison).

 * Il utilise un payload codé en dur non destructif qui affiche un extrait du
   song "in the end" by Linkin Park and then infects other binaries in the
   répertoire courant.

 * La réplication est obtenue en exécutant le binaire infecté comme un script perl 
   (basé sur perljam.pl).

 * Les en-têtes ELF, la taille du fichier et le point d'entrée ne sont pas modifiés.

 * Il fonctionne sur des binaires indépendants de la position.

 * Il n'implémente aucune technique d'évasion.

 * Testé sur Debian 12 x86_64. 

La taille de linkin.pl + payload est d'environ 2400. Une recherche rapide sur (mon) /usr/bin montre
que 817 fichiers ont assez d'espace libre pour être infectés. Interesting binaries
suitable for infection include: su, perl, cat, cp, ls.

Un compte rendu détaillé arrive bientôt. Pour l'instant, un résumé rapide du processus :

 * Parcourt le répertoire courant (non récursivement) à la recherche de cibles.

 * Inspecte les entrées 14-18 dans la table des en-têtes de section pour trouver .fini en vérifiant
   si sh_flags = 6 (AX) et sh_addralign = 4.

 * Lit l'entrée suivante de la table des en-têtes de section (.rodata) et calcule : 

      espace libre = sh_offset de .rodata - (sh_offset de .fini + sh_size de .fini)

 * Vérifie si l'espace libre > taille du payload + taille du virus.

 * Crée une copie temporaire pour appliquer les modifications.

 * Ajuste le payload pour inclure le nom du fichier binaire (voir perljam.pl).

 * Copie le payload + virus en commençant à la position sh_offset de .fini + sh_size de .fini - 1

 * Copie le reste du binaire sans changement et remplace le binaire original
   par la copie modifiée.

Si vous n'êtes pas sûr quel binaire utiliser pour tester l'infection, faites ceci :

 * Créez test.c
 ------------------------------------------------------------------------------
 #include <stdio.h>

 int main(void) {
     printf("hola mundo\n");
     return 0;
 }
 ------------------------------------------------------------------------------

 * Compilez-le : 

      $ gcc test.c -o test

 * Vérifiez l'espace libre (doit être supérieur à 2400) : 

      $ a=$(readelf -S -W a | grep ".fini " | awk '{printf $4}'); \
      b=$(readelf -S -W a | grep ".rodata " | awk '{printf $4}'); \
      perl -e "printf(qq(%d\n),(0x$b-0x$a))"

 * Exécutez Linux.Linkin.pl dans le même répertoire (aucune sortie) : 

      $ perl Linux.Linkin.pl

 * Exécutez le binaire infecté

      $ ./test
      hola mundo

Code (sur https://github.com/ilv/vx/tree/main/linkin) :
 
 Linux.Linkin.pl - code minimisé pour réduire la taille du virus.
 Linux.Linkin-packed.pl - virus empaqueté (c.-à-d. obfuscation paresseuse)
 Linux-Linkin-commented.pl - code avec des commentaires et une certaine indentation
 linkin.s - code assembleur utilisé pour générer le payload


Bugs :

 * Le message du payload ne sera pas affiché si le code .fini du binaire ferme stdout
   avant de quitter. However, you can use strace to check that the write()
   syscall is actually called.
