Je vois un virus nommé "Nasty", et la chanson qui me vient en tête est celle de Janet 
Jackson. Je suis environ 30 ans en avance.


NASTY LIMITS

Le virus commence par ouvrir le répertoire courant et lire autant d'entrées en mémoire
que possible dans un tampon de 1ko sur la pile.  This might be only a few files if the names 
are very long.  Le virus quitte si une erreur s'est produite, sinon il accepte la valeur renvoyée 
comme le nombre d'octets lus...


NASTY BUGS

Cependant, voici le premier bug : le virus continue si zéro octet a été lu.  This is 
interpreted as a buffer of enormous size.  The directory parser will then read 
uninitialised memory freely.  Le résultat est soit une boucle infinie, if a zero is read 
as the reclen value; ou il plante si une grande valeur est lue qui fait que le pointeur 
déborde du tampon.  Of course, the trigger for this bug is a very unlikely 
scenario, et facile à manquer.

Si le répertoire a été lu correctement, le virus cherche des entrées de fichiers normaux.  
S'il est trouvé, le virus essaie d'ouvrir le fichier en lecture et écriture.

Voici le deuxième bug : le pointeur de tampon est sauvegardé sur la pile avant d'essayer d'ouvrir le fichier, 
mais il n'est pas retiré de la pile si une erreur se produit.  That leads to 
an unbalanced stack on exit, which will prevent the host program from being able to 
access its command-line parameters L'environnement.  The bug would not be visible if the 
host program is very simple, c'est probablement pourquoi il n'a pas été trouvé.

Si le fichier peut être ouvert en lecture et écriture, le virus copie le nom du fichier dans un 
tampon sur la pile, immédiatement en dessous du tampon qui contient les entrées du répertoire.  
Heureusement pour l'auteur du virus, la longueur maximale d'un nom de fichier sur les systèmes de fichiers Linux 
est le plus souvent 255 caractères, so there is no risk of overrunning the 400 bytes large 
buffer.

Si le virus peut créer une carte mémoire du fichier, il analyse le contenu du fichier.
Le virus s'intéresse aux fichiers au format ELF x86 64 bits, et non déjà infectés.
Le marqueur d'infection est la chaîne "TMZ" dans le champ de remplissage.  For each file that is 
considered for infection, le virus cherche dans la table des en-têtes du programme un segment chargeable 
qui est à la fois lisible et exécutable.


EXPRESSION OF INTEREST

Pour chaque en-tête de programme qui n'est pas d'intérêt, the virus adjusts the program header 
offset in the file in order to make room for the virus.  After parsing all of the program
header entries, the virus performs the same adjustment to all of the section header 
entries.

Si le virus trouve un en-tête de programme lisible et exécutable, then the virus adjusts both 
the address and size in the entry to make room for the virus code.  The assumption is 
that one, et un seul, de ce type sera trouvé.  This could be considered a bug for 
three reasons.  Un bug est qu'il pourrait n'y avoir aucun segment exécutable, because the 
file might contain only data.  Le deuxième bug est que le segment pourrait également être accessible en écriture, 
ou avoir d'autres attributs définis.  Le troisième bug est qu'il pourrait y avoir plus d'un segment chargeable,
et le dernier sera utilisé, despite adjustments being made to the address and 
size of earlier ones.  Ces changements modifient le fichier de manière permanente, even if the infection 
process is abandoned later.  Cela complique tout effort de nettoyage, since the changes 
cannot be reversed without knowing that the virus has been run against those files.

Après l'analyse des en-têtes de section, le virus tente de créer un fichier nommé ".nty.tmp" 
dans le répertoire courant.  Si la création du fichier échoue, le fichier mappé est fuit.  
Si la création du fichier réussit, then the virus moves the location of the program header 
table and section header table up in memory, to make room for the virus code, and sets 
the new entrypoint to point to the original location de la table des en-têtes du programme, 
ajusté pour l'espace introduit pour le code du virus.

Le virus écrit dans le fichier temporaire le nouvel en-tête ELF, then the virus code, and then 
the rest of the original file.  Si tout se passe bien, le virus démappe le fichier original,
et déplace le fichier ".nty.tmp" pour remplacer le fichier original.


STOP.  HAMMER TIME

Après que tous les fichiers du tampon de répertoire aient été examinés, le virus affiche son payload

Nasty by TMZ (c) 2021

Nasty, nasty
Triple X rated
Nasty, nasty
Justice, un lieu de déchets
Nasty, nasty
Plus profondément dans la saleté
Nasty, nasty
Making bodies hurt

Ce sont les paroles de la chanson "Nasty" de The Prodigy.  Then the virus executes the host 
original entrypoint code.


CONCLUSION

Le débogage est le processus de suppression des bugs du code.  Therefore, programming is the process 
of adding bugs to code.  Nommer le virus "nasty" est approprié à plusieurs niveaux.
